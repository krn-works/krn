Each cell is `krn standards check --record ID --root ROW`. `n/a` means the record does not apply to the row (stack or need), `advisory` means it is never run.

A FAIL is a false red when the row satisfies what the record means and the record still fails. Before this change two records were false red on 4 cells: `s-semantic-commits` (php, npm, py: it judged the upstream history from before adoption; it now judges the commits since `krn.json` was first committed) and `s-php-composer-lock` (php: a library that requires only the platform asked for a lock; it now asks only when the project declares packages). - `s-test-command`, `s-php-composer-scripts` (php): the library names its test command in `krn.json` only, with no composer script.
- `s-ci-runs-tests`, `s-linter-configured`, `s-readme-test-command` (all rows) and `s-lockfile-committed` (npm): the upstream repository lacks that file or setting.
- `s-agent-state`, `s-finish-gate` pass on every row: adoption writes the `.krn/` ignore and the Stop hook, and the php row now ships one plain test (`tests/run.php`) so its canary can prove the gate.

No accepted record never applies: the `s-skill-*` records need WordPress or frontend, which no public row has, so they stay unmeasured here.
