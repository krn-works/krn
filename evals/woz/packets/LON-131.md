# LON-131 standards packet

**Governed changes.** Keep candidate proposals separate from accepted records. Bind every proposed change to its source revision, request, scope, consumer, and issue; reject ambiguous ownership, missing provenance, conflicting claims, and invalid successor links. Verification reports evidence state without mutating its source. Preserve predecessor history when records are corrected or retired. Promotion is a distinct reviewed action by the authorized owner. Emit only in the granted workspace, revalidate against current inputs, and make expected invalidity an explicit result. Tests should distinguish schema validity from authority to promote.

**Exemplar from a different accepted change.** Commit `6567b4b78fc5c5b8dae1a8536f42450f5c1c79ce` (read-only memory boundary), included in base `145a98ece9ce84dfaeeff18a1acdfcf1f55286a4`; quoted from `scripts/lib/memory/read-cli.mjs` at that base:

```js
const refuse = () => { throw new Error("memory read: invalid, unsafe or unavailable input"); };
```

This example keeps failure output generic across malformed, unsafe, or unavailable input. A proposal check must likewise avoid echoing untrusted details or treating a valid candidate as accepted truth.
