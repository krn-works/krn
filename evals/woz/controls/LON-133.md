# Irrelevant engineering control

**Topic: component composition.** Maintain one source of truth for design tokens. Give every value a stable name, intended role, reasonable bounds, and a clear owner. Generate CSS variables during the build; do not maintain a hand-edited copy of generated root styles.

Before editing a component, read its public properties and the shared composition API. Put common layout behavior in compositions and keep component-specific styling local. Avoid creating a second abstraction for one screen. Any exception should name the use case and include a focused regression case.

Check narrow and wide viewports, including long labels and alternate states. A successful build establishes syntax and dependency resolution, not visual fidelity. Record viewport and source revision with screenshots. Preserve reproducible generation and remove temporary assets when the review finishes.

For a token change, inspect derived variables and rendered consumers before merge. Compare each component default with its callers so an added option does not become a parallel convention. Keep screenshots tied to the source revision. Remove aliases after consumers move. Document the migration owner. Run a clean build before comparing output. Record the revision and viewport with each screenshot.
