# Irrelevant engineering control

**Topic: component composition.** Establish design tokens before assembling components. Each token should have a stable name, a documented role, a bounded value, and one authoritative definition. Generate root variables from token data instead of copying values into individual stylesheets.

Read the current component interface and its callers before changing layout. Shared compositions own common spacing and alignment; a component selects options through its public API. Keep global foundations, utilities, and local component rules distinct. Add an exception only when a real screen requires it and a focused regression case records the reason.

Review at narrow and wide viewports, with ordinary and extended text. A passing build detects syntax and dependency problems but cannot prove visual correctness. Record the inspected width and source revision with each capture. Keep generated files reproducible, avoid edits to compiled output, and delete temporary assets after the review is complete.

Keep breakpoint names stable across components and document the range each one represents. Avoid viewport-specific overrides when a shared composition token expresses the same rule.
