# R1-04: Start workers with an allowlisted environment

Seed ExecPlan per `docs/program/PLANS.md`. Owner: worker. Wave 1. Priority 1. Finding F-03 (P1); OWASP Agentic 2026
ASI03 (identity and privilege abuse), OWASP LLM 2025 LLM06 (excessive agency).

## Purpose / Big Picture

The worker is a prompt-injectable agent. Today it inherits the foreman's entire environment, including
`KRN_PAPERCLIP_TOKEN` in `--http` mode, so the "only the ledger writes to the board" boundary depends on the Codex
sandbox's network policy. After this change the Codex process (worker and judge) receives only an explicit allowlist and
the board credential never reaches it.

## Context and Orientation

- `src/hosts/codex.ts:176-191`: the systemd-scope path passes `env: userManagerEnvironment()` (a copy of
  `process.env` plus bus variables, `src/hosts/systemd-scope.ts:9-22`); the PID-namespace path passes no `env`, so it
  inherits `process.env` [CODE].
- `scripts/live-l1.mjs:121-126` reads `KRN_PAPERCLIP_API_URL`, `KRN_PAPERCLIP_TOKEN` into the foreman process [CODE].
- Paperclip CLI calls already use an allowlist (`src/ledger/paperclip-cli.ts:16-26`) — reuse the idea.
- Codex needs: `HOME` (auth in `~/.codex`), `PATH`, locale, terminal, temp dir, proxy variables if set, and any
  `CODEX_*` / `OPENAI_*` variables used for its own authentication [HYPOTHESIS — verify on the host with
  `codex --help` / Codex docs; R1-00 records what is available]. Codex's own `shell_environment_policy` may additionally
  filter what tool commands see; do not rely on it.
- Also move the hard-coded Codex binary default (`src/hosts/codex.ts:35-38`) behind `KRN_CODEX_BIN` (already read by
  `scripts/live-l1.mjs:192-194`) so both entry points agree.

## Plan of Work

1. New exported function `workerEnvironment(source = process.env): NodeJS.ProcessEnv` in `src/hosts/codex.ts` (or a
   small `src/hosts/worker-env.ts`): keep exactly `HOME, PATH, USER, LOGNAME, LANG, LC_ALL, LC_CTYPE, TERM, TZ, TMPDIR,
   XDG_RUNTIME_DIR, DBUS_SESSION_BUS_ADDRESS, HTTPS_PROXY, HTTP_PROXY, NO_PROXY, https_proxy, http_proxy, no_proxy` plus
   keys starting with `CODEX_` or `OPENAI_`. Drop everything else, explicitly including `KRN_*` and `PAPERCLIP_*`.
2. Use it in both spawn paths (systemd scope: `userManagerEnvironment(workerEnvironment())`; PID namespace: `env:`).
3. `defaultCodexExecutable` = `process.env.KRN_CODEX_BIN ?? <current path>`; keep the export.

(pattern from `test/hosts/codex-launch.test.ts`) writes `JSON.stringify(process.env)` to a file and emits a minimal valid

`CodexHost.start`. Assert neither sentinel appears and `HOME`/`PATH` do. Fails by assertion at base. If the test needs
