# R1-01: Refuse verdicts when the change touches the evaluator surface

Seed ExecPlan, maintained according to `docs/program/PLANS.md`. Owner: worker (Luna). Wave 1. Priority 1. Finding F-01 (P1).
Operator decision D3 (charter 2026-10-10 §3): refusal policy.

## Purpose / Big Picture

Today a worker can make `verdict` pass by editing what evaluates it. The check list comes from the base commit, but the
commands run the candidate's own `package.json` scripts and configs. After this change, `judge()` refuses — before
running any check — when the diff from base to the candidate touches the evaluator surface, and the foreman stops with
`human_decision` naming the touched path. A cheap model can no longer "pass" by redefining `npm run check` as `true`.

## Context and Orientation

- `src/verdict/registry.ts:62-78` `resolveChecks(root, base, ids)` reads `krn.checks.json` from the **base** commit
  (`git show <base>:krn.checks.json`) and returns `{id, argv, timeoutMs}` [CODE]. Schema is `version: 1`, `.strict()`.
- `src/verdict/sandbox.ts:479-565` `execute()` runs `argv` (for krn: `npm run check|lint|rules`) inside a disposable
  worktree checked out at the **candidate** SHA, so `npm` reads the candidate's `package.json` scripts [CODE].
- `src/foreman/commit.ts:18-29` protects only `.krn`, `.git*`, `.github` from worker commits [CODE].
- `src/verdict/index.ts:83-192` `judge(job, sha, base, ids, record, signal)` returns
  `{kind:'pass'|'fail'|'refused', checks, findings}`. `src/foreman/verdict.ts:135-139` turns `refused` into
  `human_decision` with the first two findings [CODE].
- Evidence that agents exploit this: ImpossibleBench (arXiv 2510.20270, 2025) and METR "Recent Frontier Models Are
  Reward Hacking" (2025-06) [EMPIRICAL].
- Test patterns for building throwaway git repos and calling `judge()`: `test/verdict/sandbox.test.ts`.

## Policy to implement (D3)

The evaluator surface is the union of:
1. Defaults, always on: `krn.checks.json`; the `scripts` object of the root `package.json` (any added, removed or
   changed key); anything under `.github/`; deletion of an existing test file (paths matching `test/**`, `tests/**`,
   `**/*.test.*`, `**/*.spec.*`).
2. Repository-declared globs from the **base** registry. Extend the registry schema with `version: 2`, which adds
   `protected: string[]` (repository-relative globs, max 64). `version: 1` stays valid and gets only the defaults.
   Update krn's own `krn.checks.json` to version 2 with
   `protected: ["scripts/**", "tsconfig.json", "biome.json", "spec/rules.json", "test/helpers/**"]`.

Finding format, one per touched item, sorted, at most 16: `evaluator surface changed: <path>` or
`evaluator surface changed: package.json#scripts.<name>`. The refusal happens before `resolveChecks` runs any command.
Use `git diff --name-status --no-renames <base> <sha>` and `git show <rev>:package.json` from the repository root; parse
`package.json` with Zod (`z.object({scripts: z.record(z.string(), z.string()).optional()}).passthrough()`); a candidate
`package.json` that fails to parse is itself a surface change. Implement glob matching with a small local function
(`*` = one segment, `**` = any depth); no new dependency (K10).

## Falsifier (red first)

New file `test/verdict/evaluator-surface.test.ts`, test name
`judge refuses a candidate that redefines a check script`:

- Build a temp repo: base commit with `package.json` `{"scripts":{"check":"node -e \"process.exit(1)\""}}`,
  `krn.checks.json` (version 1, one check `check` → `["npm","run","check"]`), `.gitignore` containing `.krn/`.
- Candidate commit changes only `scripts.check` to `node -e "process.exit(0)"`.
- Call `judge({id, issue, worktree: repo, repoRoot: repo}, candidateSha, baseSha, ['check'], async () => {})`.
- Assert `verdict.kind === 'refused'` and `verdict.findings` deep-equals
  `['evaluator surface changed: package.json#scripts.check']`.

At the merge-base this fails **by assertion**: on a host with isolation the verdict is `pass`; without isolation it is
`refused` with a sandbox error finding. After the change it passes everywhere, because the refusal precedes the sandbox.
Add a second test `judge accepts a v1 registry and a v2 registry with protected globs` (unit level on the registry
parser) and a control `judge does not refuse a source-only change for surface reasons` (assert no finding starts with
`evaluator surface changed`).

## Plan of Work

1. `src/verdict/registry.ts`: discriminated schema v1|v2; export `resolveRegistry(root, base)` returning
   `{checks, protected}`; keep `resolveChecks` behaviour.
2. New `src/verdict/surface.ts`: `evaluatorSurfaceChanges(root, base, sha, protectedGlobs): Promise<string[]>`, reusing
   the async `git` helper pattern already in `registry.ts` (do not add an eighth copy if you can import one; R1-10 will
   consolidate).
3. `src/verdict/index.ts` `judge()`: after the SHA and cleanliness checks, compute surface changes; if any, return
   `{kind:'refused', checks: [], findings}`.
4. `krn.checks.json`: version 2 with the protected list above.
5. Tests as described.

## Risks / Recovery

False refusals for legitimate config edits are intended (D3); they surface as `human_decision`. Rollback: revert the
merge commit; registry v1 files keep working.
