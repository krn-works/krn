## Purpose / Big Picture

Merges in R1 rely on a Luna panel, and the G2 review found seven blockers that Luna judges had passed. This task measures
how often the panel accepts a defective change, per role, so the operator can decide judge policy (P-004) on data.

## Plan of Work

1. Create `evals/judges/README.md` and `evals/judges/items/NN/{change.patch,truth.json}` for 10 items (stretch 20),
   each a small patch against a fixed krn base SHA (record it). At least 40% contain one planted defect from these
   classes: test weakened or skipped, evidence claimed in a different file than the change, overclaim in the commit
   message vs. diff, scope creep beyond the card, missing signal or crash handling, evaluator-surface edit.
   `truth.json`: `{defect: boolean, class, path, line, note}`. Mark truth as `provisional` until the operator confirms.
2. `scripts/judge-calibration.mjs`: for each item, create a temporary branch from the base, apply the patch, commit, run
   `node src/cli/main.ts review --repo … --base <base> --head <sha> --lens docs/program/r1/review-lens.md`, and collect
   the record. Retain each created local branch and record its branch/item/base/head mapping in the lifecycle capsule;
   this preserves reproducibility until the calibration result is accepted. Do not delete branches. Any later retirement
   needs a separate grant after the named consumer (the accepted calibration result) is finished.
3. Output `evals/judges/results-<date>.json`: per role and overall false-accept, false-reject, incomplete rate, tokens.
