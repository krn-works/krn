# R1-12: L2 — live interrupted resume, n ≤ 3, no board writes

Seed ExecPlan per `docs/program/PLANS.md`. Owner: orchestrator (runs live; Luna is the worker inside krn). Wave 3.
Depends on R1-01, R1-04, R1-05, R1-06. Breakthrough bet 3. Finding F-02. Grant: charter 2026-10-10 §6.

## Purpose / Big Picture

krn's core claim — a real task interrupted mid-way resumes in a fresh Luna session without reconstruction — has never
been demonstrated live (`evals/journeys/e1-results.json`: "Resume after a forced interruption was not proven"). This task
produces the first records, with metric v2 counters, ending at `ready_for_review` (no Paperclip writes).

## Context and Orientation

- Entry: `scripts/live-l1.mjs` (`KRN_LIVE=1 npm run live -- --job <id> --issue <ID> --repo <abs> [--worktree <abs>]
  [--http] [--submit]`). Without `--submit`, `withLiveSubmissionGate` returns `ready_for_review` and nothing is written
  to the board (`src/ledger/live.ts:31-43`) [CODE].
- The issue description must contain exactly one `krn-contract` block whose `targetRepo` matches the repo's `origin`
  (`src/ledger/live.ts:9-29`, `src/ledger/index.ts:146-164`) [CODE]. Candidates come from R1-00 step 4.
- Resume mode: re-run with `--worktree <abs .krn/worktrees/<id>>`; the foreman recovers the lease
  (`src/foreman/session.ts:217-278`) and orphaned Codex scopes are reaped on the next start
  (`src/hosts/systemd-scope.ts:55-91`) [CODE].
- Wall limit per run: `KRN_LIVE_WALL_TIME_MS` (default 20 min); session timeout 15 min (`scripts/live-l1.mjs:195-204`).

## Protocol (per record)

1. Pick an eligible issue (R1-00 list). If none exists, set `blocked`, add a `decisions.md` entry asking the operator to
   add a `krn-contract` block to named issues (the orchestrator must not edit the board), and stop this task.
2. Start: `KRN_LIVE=1 KRN_SESSION=r1-l2-<n> npm run live -- --job l2-<n> --issue <ID> --repo <abs>`.
3. Interrupt: when the job's `trace.jsonl` first shows a `checkpoint` event **and** the worker has started its next
   session (a second `session_started`), send `SIGKILL` to the `live-l1.mjs` process (not SIGTERM: this simulates a crash).
   Record the timestamp and the last trace events.
4. Resume: re-run the same command with `--worktree <abs>`; let it finish (`ready_for_review`, `human_decision`, or
   budget). Count every manual step you took as a lead intervention (`krn note --kind intervention`).
5. Evidence: `krn trace report` output (R1-11 if merged; otherwise a manual summary of `trace.jsonl`), final capsule,
   commit SHAs, verdict checks, tokens from `session_ended.end.usage`.
6. Append the record to `evals/journeys/j1-first-live.json` using `journeyLiveSchema` (R1-06). Label `n` honestly and
   list limitations (for example "single operator host", "issue already done in tracker").

## Validation and Acceptance

`evals/journeys/j1-first-live.json` parses with `journeyLiveSchema` (add a small test that loads the file), contains
≥1 record (target 3), and each record shows exactly one action after resume (no duplicate commit for the same checkpoint,
no lost commit), `reconstruction_prompts` and `lead_interventions` counted, and `outcome` taken from the run output.
Merge the record through the normal gate.

## Risks / Recovery

Live runs cost tokens; hard cap three runs plus one retry. If any run leaves a scope or process behind
(`teardown_unconfirmed`), stop live work and record it as a P1 finding.
