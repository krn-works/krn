# R1-11: Harden the trace and add `krn trace report`

Seed ExecPlan per `docs/program/PLANS.md`. Owner: worker. Wave 3. Depends on R1-06. Finding F-09; ghost feature S7.

## Purpose / Big Picture

The trace is the only source for metric v2, yet it loses error messages, has no report, and deduplicates without a
cross-process lock. After this change failures keep a bounded, redacted message, appends are serialized, and
`krn trace report --job … --worktree …` prints the run's SLIs as JSON.

## Context and Orientation

- `src/trace/index.ts:59-83` `append()` re-reads the whole file to check the key, then appends; no lock [CODE].
- `src/trace/index.ts:262-270` `failure()` stores only `errorType` [CODE].
- Secret pattern used for commits: `src/foreman/commit.ts:46-51` [CODE]. Reuse it for redaction (move it to `core` if
  needed; `core` must stay adapter-free, KRN-05).

## Plan of Work

1. Serialize `append` with the capsule lock helper (or `workspace` lock after R1-10).
2. `failure()` stores `message`: first 500 chars, newlines collapsed, secret patterns replaced by `[redacted]`.
3. `krn trace report`: JSON with `sessions`, `resets`, `checkpoints`, `commits`, `verdicts` (pass/fail/refused),
   `tokens {input, output}` summed from `session_ended.end.usage`, `lead_interventions`, `reconstruction_prompts`,
   `first_checkpoint_seconds` (from first `intent` to first `checkpoint`), `teardown_unconfirmed`.
