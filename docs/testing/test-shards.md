# Test suite sharding

`scripts/test-suite.mjs` originally set Node's `--test-concurrency=1` in the first runner commit (`ec1bd63`, 2026-10-08). `git log -S'test-concurrency'` and the surrounding history show no comment or commit rationale for that value. The original runner launched a single Node test process. Later strict evidence support also assumed one reporter event file, so each shard must now have a separate event file as well as its own `HOME` and `TMPDIR`.

The test layout contains tests that use `os.tmpdir()` and `HOME`, tests that write fixtures under the ignored repo `.krn/tmp`, and loopback servers bound to port `0`. Each shard gets its own `HOME`, `TMPDIR`, `XDG_CACHE_HOME`, `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, and `XDG_STATE_HOME`. `XDG_RUNTIME_DIR` and `DBUS_SESSION_BUS_ADDRESS` intentionally remain inherited so systemd-scope code and tests can reach the host user's systemd manager and D-Bus. Tests must not create fixtures directly in the inherited `XDG_RUNTIME_DIR`; use a private directory and set `XDG_RUNTIME_DIR` in the fixture environment. Tests that need runtime files already create private directories for them. `MISE_DATA_DIR` points to the parent's explicit `MISE_DATA_DIR`, or to the parent's `XDG_DATA_HOME/mise`, or to `HOME/.local/share/mise` when those are unset. This keeps mise-installed tools available without sharing a shard's HOME. Explicit parent `MISE_CONFIG_DIR`, `MISE_CACHE_DIR`, and `MISE_STATE_DIR` settings pass through; otherwise mise uses each shard's XDG paths. The runner resolves the parent's pnpm store once, honoring `pnpm_config_store_dir` or resolving the pinned `packageManager` through `mise where` and running that manager's `pnpm store path` from the repository root with the parent environment. It passes a successfully resolved location to shards as `pnpm_config_store_dir`; if lookup fails, it warns once and leaves the variable unset rather than guessing from HOME or XDG paths. The verdict sandbox forwards only that variable, alongside `PATH` and `HOME`, when asking pnpm for the store path; it reads the parent store before copying it into the detached copy's private store. The temp directory contains a package boundary with no declared module type so extensionless fake CLIs do not inherit the repository's `"type": "module"` setting. Node can then infer CommonJS or ESM from each fixture's syntax. Strict event files are created in unique `strict-test-events-*` directories. Port `0` gives each loopback server an ephemeral port. Most repo `.krn/tmp` fixtures use `mkdtemp`, so they have unique paths.

The final serial phase contains files with hard wall-clock assertions or process/scope teardown that must not compete with parallel shard load:

- `test/cli/delegate.test.ts`: preflight interruption must finish child termination under one second.
- `test/foreman/credential-shape.test.ts`: whole-file credential scans have a hard two-second child bound.
- `test/hosts/codex-stale-scope.test.ts`: systemd must reap a child within its runtime grace plus 1.5 seconds.
- `test/isolation-gate.test.ts`: compares repo-global `strict-test-events-*` entries before and after a child wrapper, so another wrapper could look like a leaked directory.
- `test/ledger/paperclip-cli.test.ts`: includes a 450ms timeout bound and live process-group/systemd-scope cleanup.
- `test/s4b-blockers.test.ts`: B1 cancellation must complete under 15 seconds against a 20-second host timeout; one K=4 run took 18.1 seconds. The file also exercises live process-tree and scope teardown.
- `test/trace/index.test.ts`: trace lock refusal and reclaimer assertions must complete within five seconds.
- `test/verdict/sandbox.test.ts`: live SIGTERM must tear down a verdict scope within eight seconds and the file exercises systemd/bwrap cleanup.

By default the runner uses `min(4, floor(available cores / 4))`, with a lower bound of one. `KRN_TEST_SHARDS` overrides that count. Parallel groups are balanced deterministically by assigning larger source files first to the group with the smallest total source size. Files in `SERIAL_TEST_FILES` are run in one final Node test process after parallel shards. The merged strict summary is built from all shard event streams against the full selected file list and is rejected if files are missing or duplicated, a runner fails, or its test count differs from the sum reported by the native TAP runners.

This note is for maintainers changing the test runner or adding tests that inspect shared repository state. Revisit the serial list if the global event-directory check is removed or its state is isolated; revisit the concurrency rationale if HOME, temp, fixture, or port behavior changes.
